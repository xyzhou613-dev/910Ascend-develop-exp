# 910B 推理环境基线（硬件 / 驱动 / CANN / 容器 / 框架）

本文记录 **当前推理后台**的真实环境，作为"在另一台 910B 机器上复部署"的对照基线。
数字取自现网机器实测（2026-11-02）。**所有内容可用 `scripts/env_check.sh` 一键核对**。

> 本仓库已脱敏：不含内网地址、账号口令、API key。

---

## 1. 硬件

| 项 | 实测值 | 备注 |
|---|---|---|
| NPU | **2 × Ascend 910B4-1**（chip），**每卡 HBM 65536 MB** | `npu-smi info` 查看 |
| **NPU 逻辑 ID** | **3 和 5**（不是 0/1） | ⚠️ 新机器上一定是**先用 `npu-smi info` 确认 ID**，再决定 `ASCEND_RT_VISIBLE_DEVICES` |
| **卡间互联** | **SYS**（经 PCIe + NUMA 跨节点，**无 HCCS**） | `npu-smi info -t topo`；两台设备分属不同 NUMA（CPU 亲和分别 32–63 / 0–31）。⇒ 多卡 TP 的通信走 PCIe，跨 NUMA 有明显带宽差异 |
| CPU | 华为 **Kunpeng-920 / 920 5220 @ 2.6 GHz**，**64 核**，aarch64 | `/proc/cpuinfo`、`nproc` |
| 内存 | **218 GB**（可用约 194 GB） | 长上下文/多进程时注意 RAM 也被占（PLE / 对话缓存可能放 RAM） |
| 系统盘 | 69 GB（**可用 22 GB**） | 镜像、日志放这里，容易满 |
| 权重盘 | `/models` 独立 LVM，**3.3 TB，可用 2.4 TB** | 全部权重放这里，**以 bind mount 方式进容器** |

## 9. 部署到另一台 910B 机器：最小前置清单

1. **硬件/固件**：2×910B4（或按显存需求调整）、驱动 ≥ 26.1.1、固件已装；
2. **OS/内核**：aarch64 Linux（openEuler 24.03 已验证；Kylin/Ubuntu 亦可，但需自备 NPU 驱动）；
3. **CANN 9.1.0**（宿主与容器同版本）+ `npu-smi` 可用、`npu-smi info` 能看到目标卡；
4. **Docker 18.09+**，镜像 `quay.io/ascend/vllm-ascend:v0.23.0`；
5. 容器**必须**挂载：`/models`（权重）、`/root/ascend-dev`（代码）、`/usr/local/Ascend/driver`（ro）、`/usr/local/dcmi`（ro）、`/usr/local/sbin/npu-smi`（ro）、`/etc/ascend_install.info`（ro）；
6. 权重：Flash-Next 的 `LQP` + `LQP-w4a16`（自研引擎）或 HF bf16 目录（vLLM 部署其它模型）；
7. 磁盘：`/models` ≥ 600 GB 可用（一套 Flash-Next artifact）；系统盘 ≥ 30 GB（日志）；
8. 内存 ≥ 128 GB（长上下文时 PLE/对话缓存会吃 RAM）；
9. **确认 NPU ID 与拓扑**：`npu-smi info` + `npu-smi info -t topo`；卡间是 SYS 就走 PCIe，TP 的通信开销要计入；
10. **跑一遍 `scripts/env_check.sh`**，全绿再开始部署。

## 10. 与其他平台的差异（对照用）

评测对比里还用过一台 **RTX PRO 6000 Blackwell（96 GB，单卡）**：CUDA 13 + Strata 引擎 + IQ3_S 量化。
两台机器**架构、量化、引擎、上下文策略全不同**，只能比较"同一套题、同一口径"的通过率与吞吐，
**不能**把差异归因于"卡"或"量化"其中一项（详见姊妹仓库的评测报告）。
