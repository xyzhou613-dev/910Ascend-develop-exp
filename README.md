# Ascend 开发踩坑经验集

把 **Qwen3.8-Flash-Next（121B MoE W4）在 2 × Ascend 910B4 上从零部署到 256k 上下文、17–19 tok/s 解码**
这个过程中攒下来的**可复用经验**与**踩过的坑**收在这里。每一条都有实测支撑，标了出处轮次；
"我们试过但不赚钱"的改动也一并记录，避免后人重踩。

> 环境：CANN + `torch_npu`、单机双卡 910B4（各 64 GB）、容器化部署；
> 实现与评测完整版见姊妹仓库 `qwen-ascend`。
> **本仓库已脱敏**：内网地址、账号口令、API key 均替换为占位符。

## 上车前先跑自检

```bash
bash scripts/env_check.sh                 # 默认容器名 fnx、端口 8000
bash scripts/env_check.sh -c mycont -p 8018
```

只读操作，不会启停服务；有 FAIL 时退出码非 0。本机当前结果：**PASS 18 / WARN 2 / FAIL 0**
（WARN 是 `ulimit -n=1024` 和系统盘只剩 22 GB）。

## 十条贴墙规则（先看这个）

1. **先量再改**：没有微基准，就不要说"瓶颈是带宽"。
2. **算子级测量必须独占卡**，并显式 `with torch.npu.device(dev)`；共享卡上数字会虚高。
3. **TTFT 必须用唯一 prompt**；同一 prompt 连发会命中前缀缓存，测出假值。cold / warm 两档都要报。
4. **报数字前先 `pgrep -af`** 确认跑的是哪份配置/启动脚本（我们因此吃过一次 15% "假回归"）。
5. **`systemctl stop` 不会杀容器内进程**；停完必须看 `npu-smi info` 确认显存真释放。
6. **UTF-8 文本文件不要用 PowerShell `Get-Content`/`Set-Content` 往返**——会按 ANSI 读、写出乱码。
7. 大文件走 SFTP；小文件走 base64 分片时，**分片名必须零填充**（否则 `_10` 排在 `_2` 前把文件拼坏）。
8. 任何量化/布局/拼接改动都要过**配对 NLL + 任务级门禁**（选择题、长文检索），不能只看 HTTP 200。
9. 验证"逐位一致"要用**非零状态**跑；两种实现必须用同一种归约顺序。
10. **负结果也要写下来**——它比"我们试过"值钱得多。
